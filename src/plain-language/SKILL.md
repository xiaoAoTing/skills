# 大白话翻译器

把复杂的专业内容，翻译成正常人能听懂的话。

## 什么时候用

用户说这些的时候激活：
- "说人话"
- "大白话解释一下"
- "简单点"
- "听不懂"
- "太复杂了"
- "通俗一点"

## 怎么翻译

### 1. 术语直接换掉

别解释术语，直接换成日常说法：
- ❌ "使用递归算法"
- ✅ "自己调用自己，一层套一层"

### 2. 砍掉废话

技术细节该删就删，只留核心：
- ❌ "这个 O(n log n) 复杂度的排序算法基于分治策略，通过..."
- ✅ "这个排序很快，原理是先拆开排好再合并"

### 3. 用符号说流程

别写长句子，用箭头、列表、表格：

流程用箭头：
```
打包 → 传 CDN → 拷进 core → 完事
```

对比用表格：
```
┌──────────┬────────────────────┐
│ 命令     │ 干啥               │
├──────────┼────────────────────┤
│ build    │ 只打包，不上线     │
│ deploy   │ 打包+上线，用这个  │
└──────────┴────────────────────┘
```

层级用树形：
```
src/
├── components/    # 全局都能用
└── views/
    └── user/
        └── components/  # 只有这个页面用
```

### 4. 说人话的动词

别用"执行"、"实现"、"进行"，用"跑"、"搞"、"丢"、"扔"：
- ❌ "执行部署操作"
- ✅ "跑一下 deploy"
- ❌ "将文件传输至服务器"
- ✅ "把文件丢上去"

### 5. 短句为主

一句话只说一件事，别嵌套从句：
- ❌ "这个组件通过 Context API 实现了跨层级的状态共享"
- ✅ "这个组件用 Context 共享数据。不管组件嵌套多深，都能直接拿到。"

## 翻译流程

1. **找术语** — 圈出专业词汇
2. **砍细节** — 用户不需要知道的，删
3. **换说法** — 用日常词汇替换
4. **拆句子** — 长句拆成短句
5. **加符号** — 能用图表就别用文字

## 注意

- 别过度简化，核心信息不能丢
- 技术名词可以保留，但要附带一句解释
- 看用户水平调整，有基础的可以留点术语
- 别为了通俗而说错

## 示例

**原文**：
"该组件采用 React Context API 进行全局状态管理，通过 Provider 组件在顶层注入状态，Consumer 组件在任意层级消费状态，实现了跨组件层级的数据通信。"

**翻译后**：
"这个组件用了 Context 来共享数据。

怎么玩的：
1. 顶层放一个 Provider — 相当于数据源
2. 下面任何组件都能直接拿数据 — 不用一层层传

好处：组件嵌套再深，也不用 props 传来传去。"
